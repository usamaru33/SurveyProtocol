## 0. 体制と規模（Rev.17: liberal accelerated）

判定対象は **1,052件**。

| 取得経路 | 件数 | PRISMA |
|---|---|---|
| データベース検索 | 795 | 左カラム |
| 引用探索（スノーボーリング） | 257 | 右カラム |

引用探索分には **venue フィルタ（Phase 2）とフィルタ層（Phase 1.5）を適用していない**
（理由は `snowballing_protocol.md` §4.3b）。**判定基準は両者で同一**であり、
シートの `取得経路` 列は PRISMA の左右カラム別報告のための記録にすぎない。

### 方式: liberal accelerated

> **1人が Include にすれば通す。Exclude するには2人必要。**

| 段 | 内容 | 担当 |
|---|---|---|
| **stage 1** | 全1,052件を著者が判定 | 著者 1,052件 |
| | うち**校正セット223件（20%）は3名全員**が判定 | Kataoka 223 / WATANABE 223 |
| **stage 2** | 著者が Exclude / Unsure にしたものだけ第2評価者が確認 | 2名で分担 |

**なぜこの方式か:** Phase 3b のエラーは非対称で、誤 Exclude は回復不能（全文を読む機会が
永久に失われる）だが、誤 Include は Phase 4 の手間が増えるだけ。単独スクリーニングが
関連文献を見落とす率には RCT の実測があるため、**除外の方向にだけ2名を要求**して
工数を抑えつつ感度を保つ。

> 見落とし率の具体的な数値と出典、および**引用時の過剰主張を避けるための注意**は
> [`rule.md` §5 [R1]](rule.md#5-方法論の参考文献) に集約してある。ここでは再掲しない。

**κ は校正セット223件（20%）でのみ算出する。** 除外プールだけで計算すると著者の判定に分散が無く
**κ が常に 0** になるため（`protocol_changelog.md` Rev.17）。

**割当は決定論的**（校正セットの抽出・第2評価者の振り分けとも文献キーの MD5）。
乱数を使わないので誰がいつ実行しても同じ割当になり、再生成しても記入済みの作業が無駄にならない。

## 1. 判定シートの生成

```bash
cd SurveyProtocol
python -X utf8 scripts/make_screening_sheets.py
```

続けて、評価者が実際に記入する Excel 版を作る:

```bash
python -X utf8 scripts/make_screening_xlsx.py
```

出力（`screening/`）:

| ファイル | 内容 | 誰が触るか |
|---|---|---|
| `assignment.csv` | 割当の正（record_id・block・担当2名） | **編集しない** |
| `sheet_<id>.csv` | 生成時の雛形（機械可読の正） | 触らない |
| **`sheet_<id>.xlsx`** | **各評価者の作業ファイル** | 本人のみ |

**評価者に配るのは `.xlsx` の方**。集計スクリプトは同名の xlsx があればそちらを
優先して読むので、CSV は雛形として残しておいてよい。

### Excel 版に入れてある補助

| 機能 | 目的 |
|---|---|
| 判定列のドロップダウン（Include/Exclude/Unsure） | 表記ゆれを構造的に防ぐ。集計時の不正値がゼロになる |
| **除外理由列のドロップダウン（9択の統制語彙）** | 理由別の除外件数をそのまま報告できる。3名の表記の割れを防ぐ |
| 理由が「その他」なのにメモが空のセルを赤字強調 | 統制語彙の逃げ道が、記述を伴わないと意味を失うため |
| 見出し行＋ID列の固定 | 横スクロールしても列の意味と対象を見失わない |
| オートフィルタ | 「判定が空白」で絞れば未記入だけ表示できる |
| 要旨欠落行の淡い赤 + `要旨有無` 列の `N` | **色だけに意味を持たせない**。フィルタでも絞れる |
| Exclude なのに理由が空のセルを赤字強調 | 提出前の自己チェック |
| 記入3列以外をロック | 誤編集の防止（パスワードなし。行・列幅の変更と並べ替え・フィルタは許可） |
| 見出しのコメント | 各列の意味を別紙なしで確認できる |
| 「はじめに」シート | 手順・判定の考え方・要旨の全文表示方法 |

> **要旨の表示について:** 要旨は中央値1,278字あり、セルに全文を収めると1行が15行分の
> 高さになって走査できなくなる。既定は「タイトル全文＋要旨の冒頭5行」が見える高さ（85pt）に
> しており、全文を読むときは行の高さの自動調整か数式バーの拡張を使う。手順は
> 「はじめに」シートに書いてある（行の書式変更はシート保護から除外済み）。

> **既存シートは上書きされない。** 記入途中で再生成しても作業は消えない
> （存在するファイルはスキップされる）。コーパスが変わって作り直したい場合は、
> 旧シートを退避してから実行すること。

### なぜ評価者ごとに別ファイルなのか

二重スクリーニングの妥当性は **評価者が互いの判定を見ないこと** に依存する。
1枚のシートに両者の列を並べると、先に書いた側の判定が後の側から見えてしまい、
独立性が壊れて κ が意味を失う。**他人のシートは開かないこと。**

## 2. 記入のしかた

各自、自分の `sheet_<id>.csv` の以下2列を埋める。

| 列 | 記入内容 |
|---|---|
| `decision` | `Include` / `Exclude` / `Unsure` のいずれか（大文字小文字は問わない） |
| `reason` | **Exclude のときは必須**。下の統制語彙から1つ選ぶ（xlsx ではドロップダウン） |
| `note` | 任意。協議で持ち出したい論点など。**`reason` が `その他` のときは必須** |

### 除外理由の統制語彙（Rev.18）

自由記述をやめたのは、PRISMA が求める除外理由の記録を**そのまま集計できる形**にするため。
自由記述だと著者が事後にコーディングすることになり、その作業自体が判定への事後介入になる。
定義の正は `scripts/make_screening_xlsx.py` の `EXCLUDE_REASONS`。

| 選択肢 | 定義 |
|---|---|
| `P: 対象者が不適合` | 健常成人でない（小児・高齢者・患者・特定の専門職集団など） |
| `I: HMD-VR でない` | デスクトップ画面・AR/MR・CAVE・実環境のみなど |
| `I: スケール操作/多感覚刺激が無い` | 身体・空間スケールの操作も多感覚刺激の提示も行っていない |
| `O: スケール知覚の測定が無い` | 自己・環境のスケール変容を測る定量指標が無い |
| `S: ユーザー実験が無い` | 技術提案・デモ・シミュレーションのみ |
| `S: 原著論文でない` | 総説・サーベイ・抄録のみ・ポスター・基調講演・書籍など |
| `スコープ外(主題が無関係)` | 基準を当てるまでもなく本レビューの主題と無関係 |
| `重複(同一研究の別報告)` | 既に対象に含まれている研究の別報告・拡張版 |
| `その他` | 上のどれにも当てはまらない。**メモに理由を必ず書く** |

- **複数該当するときは、下記の優先順位で最も上位のものを1つ**選ぶ。**併記は求めない**
  （`note` への書き足しは不要。`note` が必須なのは `その他` を選んだときだけ）。
- **`C`（比較対象）は選択肢に無い。** 比較条件は要旨に書かれないことが多く、
  この段階で C を根拠に落とすと誤除外（回復不能）になる。判断は Phase 4 に送る。

> ### 除外理由の優先順位（2026-08-24 追加 / `protocol_changelog.md` Rev.24）
>
> **複数該当するときは、下の順位で最も上位のものを1つ記録する。**
> 「最も明白なもの」は評価者ごとにぶれるため、順位を固定して決定論にした。
>
> | 順位 | 選択肢 |
> |---|---|
> | 1 | `重複(同一研究の別報告)` |
> | 2 | `スコープ外(主題が無関係)` |
> | 3 | `S: 原著論文でない` |
> | 4 | `S: ユーザー実験が無い` |
> | 5 | `P: 対象者が不適合` |
> | 6 | `I: HMD-VR でない` |
> | 7 | `I: スケール操作/多感覚刺激が無い` |
> | 8 | `O: スケール知覚の測定が無い` |
> | 9 | `その他`（他の8つに当てはまらないときのみ） |
>
> **原理: 上位ほど、下位の基準を評価する前提そのものが崩れている。**
> 重複＝独立した研究として数えない → スコープ外＝PICOS を当てる対象でない →
> S 2つ＝研究の実体が無く P/I/O を評価できない → 実体のある研究に PICOS を順に適用。
>
> **併記は求めない。** 選ばなかった理由を `note` に書き足す必要はない。
> したがって**理由別の集計は「上位に一本化された件数」であり、内訳は復元できない**
> （→ Threats to Validity）。
>
> **Include/Exclude/Unsure の判定は変わらないため κ に影響しない。**
> 目的は、Rev.21 の κ 低下時診断（除外理由の分布から割れた基準を特定する）を機能させること。
>
> 語彙・シートは**変更していない**（Rev.19 の凍結維持）。

> **`S: 原著論文でない` の解釈（2026-08-20 補足 / `protocol_changelog.md` Rev.20）**
>
> 上表の語彙定義に含まれる「ポスター」は、**実験を伴わない**ポスター発表を指す。
> **実験を報告しているポスター/ショートペーパーは Include**（Rev.14 の S 基準運用）。
> ページ数ではなく内容で判断する。
>
> 語彙の文言は配布時のまま**変更していない**（Rev.19 の凍結維持）。
> 公開する語彙表と運用解釈が一字一句同じでない点は Threats to Validity で報告する。
- 「その他」の件数と内訳は Threats to Validity で報告する。一定数を超えたら語彙を見直す。

> 選択肢は Excel の隠しシート `_選択肢` に置き、範囲参照で指定している。
> インラインの選択肢リストは Excel 仕様で 255 文字上限があり、日本語では溢れるため。

### 判定基準

`rule.md` の PICOS を **Title/Abstract レベルに緩めたもの**で判定する。

- **除外できると確信できないものは残す**（Include 側に倒す）。全文を読めば分かることを
  この段階で切らない。
- 迷ったら `Unsure`。Unsure は協議対象になるので、無理に二択にしない。

### 参考列（判定には使わない）

| 列 | 意味 |
|---|---|
| `kw_groups` | Rev.6 統合クエリの3概念群が Title+Abstract にいくつ成立するか（0〜3）。**読む順序のトリアージ専用**。シートはこの降順→新しい年順に並べてある。この値で機械的に除外してはならない |
| `calibration` | `Y` は3名全員が判定する校正セット（κ の算出に使う）。`N` は著者がまず判定し、Exclude になったものだけ第2評価者が確認する。**判定基準はどちらも同じ** |
| `has_abstract` | `N` は**要旨が無くタイトルだけで判定することになる**文献 |
| `abstract_source` | `database`=検索結果に元からあった / `enriched`=DOI から外部補完（134件）/ `none`=取得できず。**`enriched` も判定材料としては同じように使う** |
| `rank` | 掲載先の CORE/SJR ランク。Phase 2 で既に基準を満たしているので、判定材料にはしない |

> ⚠️ **要旨欠落 191件（18.2%）** — Rev.16 で DOI から134件を外部補完した結果。
> 補完前は325件（30.9%）だった。内訳は DB検索側63件 / 引用探索側128件で、引用探索側に
> 偏っているのは引用メタデータが DOI しか持たないことが多く、Semantic Scholar 側にも
> 要旨が無いため。この191件は**タイトルのみでの判定**になる。無理なら `Unsure` にして協議に回すこと。 — Rev.13 で重複コピーからのマージにより大幅に回収したが、
> どのコピーにも要旨が無いものが残っている。これらは Phase 1.5 で `hold`（判定不能）として
> 保留されたレコードで、**タイトルのみでの判定**になる。無理なら `Unsure` にして協議に回すこと。
> 件数は Threats to Validity に明記する。

## 4. 集計と協議

全員の記入が終わったら:

```bash
python -X utf8 scripts/score_screening.py
```

出力されるもの:

1. **記入状況の検査** — 未記入・不正値・担当外レコード・Exclude なのに reason が空、を検出
2. **ペアごとの Cohen's κ とその平均**（3カテゴリ版が主報告。Unsure→Include に寄せた
   2カテゴリ版も参考として併記される。どちらを本文に載せるかは著者が決めるが、
   **両方を出したうえで選ぶ**ことで恣意的に見えないようにしている）
3. `screening/consensus_worklist.csv` — 不一致と Unsure だけを抜いた協議リスト
4. **κ の閾値判定と、発動すべき対応**（Rev.21。下記）

### κ が基準を下回った場合（Rev.21、2026-08-20 事前確定）

**判断に用いるのは3カテゴリ版のペア平均。** 2カテゴリ版は参考であり閾値判断に使わない。

| κ（ペア平均） | 対応 |
|---|---|
| **≥ 0.61** | 予定どおり続行 |
| **0.41 – 0.60** | 不一致・Unsure を全件協議 → **不一致文献の除外理由の分布を検査** → 特定基準に集中していれば**その基準に該当する全件を3名で再判定** |
| **< 0.41** | stage 2 を拡大し、**著者が Include にしたものも第2評価者が確認**（実質的な全件二重化） |

いずれかのペアが単独で 0.41 未満なら、そのペアの stage 2 分に下位段の対応を適用する。

**κ の値によらず、実測値・解釈・発動した対応を必ず本文に記載する。**
**校正セットの一部を除いて計算し直す / 2カテゴリ版に切り替えて基準を満たしたことにする /
κ を報告しない**——これらは明示的に禁じられている（`rule.md` §Phase 3b）。

> 本方針は**判定結果を見る前**（当時の締切 2026-08-26 より前。締切はその後 Rev.24 で 2026-08-31 へ延長）に確定した。
> `score_screening.py` が該当する対応を自動で表示する。

協議リストの `final_decision` と `consensus_note` を協議で埋める。

> **協議で解決しない場合は `Include` に倒して Phase 4 へ送る**（再現率優先、
> `rule.md` Phase 3b）。その場合は `consensus_note` に「協議で解決せず → Include」と
> 明記すること。後から件数を数えられる状態にしておく。

再度 `score_screening.py` を実行すると、未解決がゼロなら
`screening/final_decisions.csv`（最終判定）が生成される。Include のものが Phase 4 へ進む。

## 5. 報告に必要な数値

PRISMA / 本文に載せるため、以下を `score_screening.py` の出力から転記する。

- ペア別 Cohen's κ（3本）とその平均、Landis & Koch の解釈
  **— 校正セット223件（20%）で算出したものであることを明記する**
- liberal accelerated で1名の Include により通過した件数（第2評価者を経ていない分）
- 一致件数 / 要協議件数（不一致・Unsure の内訳）
- 協議で解決した件数 / 解決せず Include に倒した件数
- Phase 3b の Include 件数（= Phase 4 の対象）と Exclude 件数

`screening/` 一式（割当・各評価者のシート・協議リスト・最終判定）は
**監査可能性のため supplementary material として公開する**。

> **バージョン管理での扱い（注意）:** 各評価者のシート `sheet_*.csv` / `sheet_*.xlsx` は
> **記入中は `.gitignore` で追跡しない**。3人分がリポジトリに入ると互いの判定が
> 見えてしまい、独立性が壊れるため。ただしこれらは `rule.md` が要求する監査証跡でも
> あるので、**スクリーニング完了後に `git add -f screening/sheet_*.csv` で必ず
> 追跡に加える**こと。割当表・協議リスト・最終判定は最初から追跡している。

## 6. 既知の制約

- **要旨欠落 191件** は上記のとおり（左63 / 右128）
- 判定は人間の主観に依存する。緩和策は二重評価・κ の報告・協議記録の公開だが、
  主観であること自体は消えない（Threats に明記済み）
- `kw_groups` によるトリアージは読む順序を変えるだけで、判定対象は全件のまま。
  **順序が判定に与える影響（先に読んだものほど厳しく/甘くなる等）は統制していない。**
  これも Threats の候補

## 7. 記入見本（配布時に一緒に渡す）

評価者に判定シートを配るとき、**記入の仕方を示す見本**を一緒に渡す。

```bash
python -X utf8 scripts/make_screening_example.py
```

出力: `screening/EXAMPLE_記入見本.xlsx`（全員に同じものを配る）

5件の例で次を示している。

| ID | 判定 | 示している論点 |
|---|---|---|
| EXAMPLE-1 | Include | 典型例。理由欄は Include なら空でよい |
| EXAMPLE-2 | Exclude | `P: 対象者が不適合` — 複数該当するときは優先順位で1つに絞る（併記は不要） |
| EXAMPLE-3 | Exclude | `I: HMD-VR でない` — 実験は良質でも I 基準で落ちる |
| EXAMPLE-4 | Exclude | `S: ユーザー実験が無い` — 技術提案・デモ |
| EXAMPLE-5 | Unsure | 迷ったら無理に二択にしない |

> 見本の `reason` が統制語彙から外れていると生成がエラーで止まる。
