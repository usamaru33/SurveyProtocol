## 役割の分担

| 誰が | 何をするか |
|---|---|
| LLM | 17 列それぞれについて、関係する箇所を論文から探し、原文のまま頁つきで抜き出す |
| スクリプト | 抜き出された引用が、全文テキストに一字一句あるかを検査する。無い引用は捨てる |
| 抽出担当者 | 引用を読んで、17 列の値を書く。語彙の選択、`main_finding` の 1 文も担当者が書く |

LLM は値を書かない。要約、翻訳、分類、判定もしない。

## 使い方(予定)

- 入力は、`fulltext/txt/<record_id>.txt`(全文 PDF から機械的に取り出したテキスト。頁の境目に `[p.N]` の印がある)。
- 渡すのは全文テキストと record_id だけ。人手の判定結果や、他の論文の結果は渡さない。
- 出力の JSON を、そのまま保存する。モデル ID、実行日、プロンプトの版も一緒に記録する。
- 同じ論文を 3 回処理し、列ごとに、抜き出された引用の集合が同じかを比べる。
- 引用が 0 件の列は、担当者が本文を自分で確かめてから `記載なし` と書く。

## プロンプト本文

```text
これは、VR における自己スケール感覚の系統的レビューで使う作業です。レビューの担当者は、
各論文から 17 項目の事実を読み取って記録します。あなたの仕事は、担当者が読むべき箇所を
論文の中から探して、原文のまま示すことです。値を読み取って記録するのは担当者なので、
あなたは引用だけを返します。

<paper> タグの中に、1 本の論文の全文テキストがあります。頁の境目には [p.N] の印が
入っています。下の 17 項目それぞれについて、その項目の値を決めるのに必要な箇所を
抜き出してください。

引用の決まり
- <paper> の中の文字列を、そのまま写してください。あなたの出力は、プログラムが
  <paper> の中を文字列検索して照合します。1 文字でも違う引用は、存在しないものとして
  捨てられます。そのため、綴りの誤りや、行末のハイフン、記号も、テキストにあるとおりに
  写します。言い換え、要約、翻訳、省略記号(…)による中略はしません。
- 1 つの引用は、1 文から 3 文程度の、ひと続きの範囲にします。離れた箇所は、別の引用に
  分けます。
- 頁は、その引用の直前にある [p.N] の番号です。引用が頁の境目をまたぐ場合は、
  境目で 2 つの引用に分けます。
- その項目に関係する箇所が複数あれば、すべて挙げます。たとえば、参加者数が要旨と
  方法の節の両方に書かれていれば、両方を挙げます。実験が複数ある論文では、
  すべての実験の箇所を挙げます。担当者は、あなたが挙げなかった箇所を読まない
  可能性があるので、迷う箇所は挙げる側に倒してください。
- 関係する箇所が論文に無ければ、その項目は空の配列にします。関係の薄い箇所で
  埋める必要はありません。

あなたが書くのは引用と頁だけです。値の読み取り(人数を数える、選択肢から選ぶ、
結果をまとめる)、論文をレビューに含めるかどうかの評価、研究の分類や質の評価は、
人が別の手順で行うので、出力に含めないでください。

項目(探す箇所)
1. n_total: 参加者の人数。除外する前の全体の人数が分かる箇所。
2. n_analyzed: 分析に使った人数。参加者の除外や脱落、最終的な人数が分かる箇所。
3. population: 参加者の属性(学生、一般募集など)、年齢、性別が分かる箇所。
4. device: 使った HMD の機種名が分かる箇所。
5. scale_target: 何のスケールを変えたかが分かる箇所。身体全体、身体の部位、
   視点の高さ、瞳孔間距離(IPD)、環境、物体のいずれを操作したか。スケールを操作せず、
   測定だけを行った研究なら、そのことが分かる箇所。
6. scale_factor: 操作の倍率や値が分かる箇所(例: 0.5 倍、2 倍、視点の高さ 1.7 m)。
7. scale_direction: 縮小したのか、拡大したのか、両方かが分かる箇所。
8. non_visual: 視覚以外の感覚(聴覚、触覚、歩行や身体動作との同期、前庭感覚など)を
   提示したかどうかが分かる箇所。
9. non_visual_detail: 視覚以外の感覚を、何をどう提示したかが分かる箇所。
10. action_contingent: 視覚以外の手がかりが、参加者自身の動作に連動して生じるか
    どうかが分かる箇所。
11. task: 参加者が行った課題が分かる箇所(距離の推定、サイズの推定やマッチング、
    リーチや把持、歩行や移動、アフォーダンスの判断、身体サイズの判断、質問紙への回答など)。
12. outcome_measures: 測定した項目と、その測り方が分かる箇所(主観報告、質問紙、
    行動の指標、生理の指標)。質問紙の名称もここに含めます。
13. social_context: 参加者が仮想空間に 1 人でいたか、他のアバターや人物がいたかが
    分かる箇所。
14. individual_diff: 参加者の特性(身長、VR の経験、性別、年齢)を記録した、または
    分析に使ったことが分かる箇所。
15. null_effect: スケール操作の効果が有意でなかった条件や指標が分かる箇所。
16. main_finding: 著者が主な結果を述べている箇所。結果の節の要点、考察の冒頭、
    結論、要旨の結果の文。
17. attribution_quote: 知覚の変化を、自分の身体が変わったことによるものと述べているか、
    周囲の世界が変わったことによるものと述べているかが分かる箇所
    (例: 自分が小さくなったと感じた、世界が大きく見えた、という趣旨の記述)。

出力
次の形の JSON だけを出力してください。前置きや説明は付けません。17 項目すべてのキーを、
この順で含めます。

{
  "record_id": "<渡された ID>",
  "fields": {
    "n_total": [{"quote": "<原文そのまま>", "page": 4}],
    "n_analyzed": [],
    "population": [{"quote": "<原文そのまま>", "page": 4}, {"quote": "<原文そのまま>", "page": 5}]
  }
}

<paper record_id="{record_id}">
{full_text}
</paper>
```

## 検査(スクリプト、決定論的)

1. JSON として読めること。17 個のキーがすべてあること。
2. 各引用が、全文テキストの該当頁に、文字列として存在すること(空白と改行の違いだけは無視する)。無い引用は捨て、件数を記録する。
3. 3 回の実行で、列ごとの引用の集合が一致するかを比べ、一致しない列を一覧にする。

## 未決の点

1. **3 回の出力が食い違ったときの扱い。** 決定: 3 回分を重ねて(同じ箇所は 1 つにまとめて)担当者に見せる(2026-11-18)。重ねる処理は未実装。
2. **引用が 0 件の列。** 担当者が本文を確かめる、という条件を `rule.md` に書く。
3. **頁番号。** `[p.N]` は PDF の通し頁になる。雑誌の頁番号とずれる。`attribution_quote` の `(p.N)` をどちらで書くか。
4. **全文テキストの質。** 2 段組や表は、PDF からの取り出しで文字の順が崩れることがある。表の中の数値は、引用として拾えない場合がある。
5. **モデルと設定。** モデル ID と設定を決め、出力と一緒に記録する。
