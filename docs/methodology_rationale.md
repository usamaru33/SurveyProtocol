> **目的:** 26,434件がどうやって1,052件になったか、**各段が何のために置かれているか**を
> 説明できる形にまとめたもの。想定質問への回答つき。
> **作成:** 2026-08-20 / 数値はすべて実データに突き合わせて検証済み

関連文書: `rule.md`（プロトコル本体）/ `protocol_changelog.md`（全改訂履歴）/
`reviewer_briefing.md`（評価者向け説明会資料）

**設計を貫く2つの原則:**

1. **判定に AI/LLM を一切使わない**（`rule.md` Rev.2）。すべての機械的な段は決定論的で、
   誰がいつ実行しても同じ結果になる。原稿にも
   *"no large language model was used at any eligibility decision point"* と記載する。
2. **機械的な段は「適格性」を判定しない。** 主題が適合するかの判断は Phase 3b 以降の
   人手だけが行う。前段は「取得の偏りを均す」「明らかに範囲外を落とす」に限定する。

## 1. Phase 1 — 重複削除とフィールドマージ

**何をするか:** DOI → Key → Title の順で重複を検出し、1レコードに統合する。

**意図:** 同じ論文が3つのDBから別レコードとして入ってくる。これを潰さないと件数が
水増しされ、PRISMA の報告も判定工数も歪む。

### ★ フィールドマージを追加した理由（Rev.13）

当初の重複削除は「先出優先」で、**要旨を持つコピーを捨てて要旨の無いコピーを残していた**。
ACM が Scopus より先に並んでいるという、それだけの理由で。

実測で、要旨欠落7,375件のうち **3,439件が同じ論文の別コピーに要旨を持っていた**。
外部APIを使わず回収できるので、統合時に**フィールド単位でマージ**するよう変更した。
最終的に Abstract 4,172件 / ISSN 1,474件 を回収している。

> **意図:** 判定材料（要旨）の欠落は、後段で「タイトルだけで判定する」という
> 品質低下に直結する。**メタデータの取り違えによる情報損失は、方法論の問題ではなく
> 単なる実装の欠陥**なので、潰しておく。

## 2. Phase 1.5 — フィルタ層（最も説明が要る段）

**何をするか:** 取得後に、検索クエリ（Rev.6 の G1∧G2∧G3）を全レコードへ**もう一度**
一律に適用する。3概念群すべてが Title+Abstract で成立しないものを落とす。

| 概念群 | 内容 |
|---|---|
| G1 | 没入環境（virtual reality / VR / HMD / head-mounted display / virtual environment / immersive …） |
| G2 | 身体表象（body / avatar / embodiment …） |
| G3 | スケール知覚（size / scale / height / distance …） |

**除外 12,025件。パイプライン最大の除外段。**

### なぜ必要か — DBごとに検索の当たり方が違う

これは推測ではなく実測です。

| DB | 実際の検索scope |
|---|---|
| Scopus 第1波 | `TITLE-ABS-KEY`（キーワード欄も含む） |
| Scopus 第2波 | `TITLE-ABS`（Rev.11 で変更） |
| IEEE 第1波 | より広いフィールド指定。**第2波に現れない1,077件のうち、TAで3概念群が成立するのは 4.7% だけ** |
| ACM 第2波 | Title検索とAbstract検索の**和集合**（フィールド横断の一致を落とす） |

**このまま統合すると「どのDBで拾われたか」によって適格性が変わってしまう。**
同じ主題の論文が、Scopus に載っていれば残りIEEEにしか無ければ落ちる、という
**DB由来の恣意性**が入る。フィルタ層はこの差を吸収するために置く。

### 配置の理由

| 位置 | 理由 |
|---|---|
| **重複削除より後** | 同じ論文のACMコピーとScopusコピーで判定が割れる。マージ後の1レコードに1回だけ適用する |
| **Venueランク・キーワード除外より前** | 「取得の差を均す処理」であって「適格性で落とす処理」ではない。**性格の違う段として分けて報告する** |

### ★ フェイルセーフ（設計の要）

**要旨が無いレコードは「判定不能」であって「不適格」ではない。**

タイトルのみで判定すると要旨欠落567件のうち566件が落ちる。これは中身ではなく
**メタデータ品質による除外**であり、正当化できない。判定不能は `hold` として保留し、
人手へ送る（pass 2,610 / hold 3,707）。

### ★ 2026-08-15（Rev.14）に一度見直し、維持を決めている

gold set を17件に拡充したとき、**フィルタ層が2件（#24 Okada / #25 Pouke）を落とす**
ことが判明した。3案を実測比較している。

| 案 | Phase 1.5 通過 | 最終候補 | 工数/人 | gold 脱落 |
|---|---|---|---|---|
| **3群必須（採用）** | 6,317 | **795** | 530件 | 2件 |
| G1に`virtual`・G2に`user/self`を追加 | 8,112 | 1,131 | 754件 | 0件 |
| 2群以上に緩和 | 11,110 | 1,665 | 1,110件 | 0件 |

**語彙追加を採らなかった理由:** #25 を救うには G2 に `user` が必要だが、これは
**あらゆるHCI論文に出る語**で、身体表象の概念群として機能しない（G2 の pass が
2,610 → 3,698 に膨らむ）。却下済みの「キーワードスコア案」と同じ問題
（語彙・閾値の根拠を説明できない）に戻ってしまう。

**2群以上を採らなかった理由:** goldは全て救えるが最終1,665件となり、
**概念群のAND条件という検索式の骨格が崩れる**。

**採った立場:** #24/#25 の脱落は**フィルタ層の欠陥ではなく検索クエリ自体の語彙的限界**
（#24は本文が `virtual self-touch`、#25は `scaled-down users` で、そもそもクエリの語彙に
当たらない）。これらがコーパスに存在するのは第1波IEEEの広いscopeに拾われた偶然による。
**Threats to Validity で報告し、スノーボーリングで回収する**対象として扱う。

> **この判断は結果的に正しかった。** §5 のとおり、スノーボーリングは実際に
> Being Barbie を含む3件を回収している。

### 引用探索側には適用しない（Rev.15）

判定対象1,052件のうち、**引用探索の257件はフィルタ層を通っていない。**
目的が「**DB間の検索scope差の吸収**」であり、DB検索で取得していない文献には
**吸収すべき差が存在しない**ため。適格性の基準ではないので、適用しなくても
判定基準は変わらない。

### 要旨補完後に再適用しない（Rev.16）

Rev.16 で DOI から要旨を134件補完したが、その後に Phase 1.5 を再適用していない。

1. **検索が一度も見ていないテキストで判定する**ことになる
2. フィルタ層のフェイルセーフ（メタデータ欠落を理由に除外しない）と**逆行する**

## 3. Phase 2 — Venue ランク

**何をするか:** 掲載先が **CORE A/A\*** または **SJR Q1** のものだけを通す。

**意図:** ACM Computing Surveys 投稿を前提に、**査読の質が担保された場**に絞る。
主題ではなく**掲載先**で切るので、決定論的に実行でき、恣意性が入らない。

### 通過と除外の実測（入力 6,317件）

| 通過 | 件数 | | 除外 | 件数 | 割合 |
|---|---|---|---|---|---|
| CORE A/A* | 318 | | **Venue未照合（CORE/SJRに無い）** | **3,085** | **60.0%** |
| SJR Q1 | 838 | | CORE 低ランク（B/C等） | 1,165 | 22.7% |
| エイリアス経由 | 23 | | SJR 非Q1（Q2/Q3/Q4/-） | 888 | 17.3% |
| **合計** | **1,179** | | **合計** | **5,138** | |

### ⚠️ この段が最大の弱点

**除外の60%（3,085件）は「ランクが低いから」ではなく「照合できなかったから」落ちている。**
これは質の判断ではなく**名寄せの失敗**であり、Threats to Validity の筆頭項目になる。

対策として Rev.12 で正規化に構造ガード（種別マーカー・短キーガード）を入れ、
`venue_aliases.csv` を最優先に据える設計へ改めた。監査列 `Match_Stage` /
`Match_Guard_Note` を出力に追加し、誤照合を可視化できるようにしてある。

**Known-Item も6件がこの段で落ちている。** これがスノーボーリングを行う直接の動機になった
（`snowballing_protocol.md` §0）。

### SJR Q2 を採らなかった件

Q2まで広げると826件/332誌が加わる（Rev.4 で Q1 のみに確定）。この中には
Multisensory Research・QJEP・Neuropsychologia など**主題に関連する誌が含まれる**ため、
Threats で**具体名を挙げて**報告する方針。

## 4. Phase 3a — キーワードによる決定論的除外

**何をするか:** Title+Abstract に対する正規表現マッチ（大小文字無視・単語境界 `\b` 適用）。
マッチしたものを除外する。**除外 384件。**

| カテゴリ | 件数 | 内容 |
|---|---|---|
| Cat1 非没入 | 112 | デスクトップ・2D画面など、HMDでないことが語彙で確定するもの |
| Cat2 技術・非実証 | 24 | 技術提案のみでユーザー実験を伴わないことが確定するもの |
| Cat3 臨床・医療 | 262 | 患者・治療・リハビリなど、P基準に明確に反するもの |

**意図:** PICOS に**明確に反することが語彙で確定できる**ものだけを、人手の前に落とす。
判断が要るものは一切落とさない。全パターンと追加理由は `rule.md` に表として記録済み。

> **なぜスコアリングにしないか:** キーワードスコア案は検討のうえ却下している。
> **語彙の重みと閾値の根拠を説明できない**ため。決定論的な正規表現なら、
> どの文献がなぜ落ちたかを1件ずつ再現・監査できる。

## 5. 引用探索（スノーボーリング）— +257件

**何をするか:** 既知の適合文献をシードに、後方（引用文献）・前方（被引用）をたどる。

**意図（2つに分離、Rev.10）:**

| 目的 | 内容 |
|---|---|
| (A) 回収 | **Venueフィルタで脱落した Known-Item の回収** |
| (B) 探索 | まだ誰も気づいていない主題適合文献の発見 |

### ★ 実測: 目的(A)は達成されている

| 対象 | Known-Item(in-scope) 17件のうち残存 | recall |
|---|---|---|
| DB検索のみ（step3 = 795件） | 5 | 29.4% |
| **判定対象 1,052件（引用探索を加算）** | **8** | **47.1%** |

**引用探索が3件を回収した**（Being Barbie 2011 / plausibility paradox 2020・2021）。

**Being Barbie は、検索式が構造的に取りこぼすと特定されていた文献**である
（G1に命中せず、PLoS ONE は索引済みなので**ライブラリ追加では直らない**）。
**クエリのギャップを引用探索が実際に埋めた**直接的な証拠であり、
引用探索が「念のため」ではなく**検索式の既知の欠陥に対する機能的な補完**だったことを示す。

再現: `python -X utf8 scripts/known_item_screening_audit.py`

> **報告時の注意:** 47.1% は依然として低い。「引用探索で解決した」ではなく
> **「29.4% → 47.1% に改善したが限界が残る」**が正確な記述。

## 6. Phase 3b — 人手による Title/Abstract 判定

ここから先は機械を使わない。詳細は `screening_protocol.md` / `reviewer_briefing.md`。

- **方式:** liberal accelerated（1人がIncludeにすれば通す / Excludeには2人必要）
- **校正セット164件**を3名全員が判定し、そこでのみ Cohen's κ を算出
- **除外理由は9択の統制語彙**（PRISMA の「理由別除外件数」をそのまま報告するため）
- **原則:** 除外できると確信できないものは残す（誤Excludeは回復不能）

> ### ⚠️ Rev.20（2026-08-20）の解釈明示を必ず伝えること
>
> 統制語彙 `S: 原著論文でない` の定義に「ポスター」が入っているが、これは
> **Rev.14 で確定した運用（実験を報告していればポスター/ショートペーパーも Include）と
> 矛盾していた。** 配布済みシートは凍結のため語彙を変えず、**解釈を明示する**ことで解消した。
>
> - 該当する: 総説・サーベイ・基調講演・書籍、**実験の記述がない**抄録
> - **該当しない: 実験を報告しているポスター/ショートペーパー → Include**
> - **ページ数は除外理由にならない。判断するのは内容。**
>
> 多感覚系はポスター発表が多く、除外すると**本サーベイの主張の根拠が痩せる**
> （§5 の gold set にも IEEE VR の2ページ論文が3件ある）。

## 7. 設計の背骨（一段ずつではなく全体を貫くもの）

| 原則 | 具体化 |
|---|---|
| **決定論性** | 機械的な段はすべて再実行可能。割当（校正セット・第2評価者）も乱数ではなくMD5 |
| **LLM不使用** | 適格性判定に一切使わない。記入見本すら「既存の記録の転記」で作り、判定対象に触れていない |
| **誤除外の非対称性** | 回復不能な方向（Exclude）にだけ重い手続きを課す。liberal accelerated / フェイルセーフ / 迷ったらInclude |
| **段の性格を混ぜない** | 「取得差の吸収」（P1.5）と「適格性」（P2以降）を分けて報告する |
| **監査可能性** | `screening/` 一式を supplementary material として公開。誤照合の監査列も出力に含める |

# 8. 想定質問

## A. 評価者（Kataoka さん・WATANABE さん）から出そうなもの

**Q1. 26,434件から1,052件まで、97%近く落としている。落としすぎでは？**

段ごとに性格が違います。最大の除外はフィルタ層（12,025件）ですが、これは
**主題で落としているのではなく、DBごとの検索の当たり方の差を均している**段です。
「3つの概念群すべてがタイトルか要旨に出る」という、元の検索式と同じ条件を
全レコードに揃えて適用しているだけです。

適格性で落としているのは Phase 3a の384件だけで、しかもそれは
「患者対象」「デスクトップ」など**語彙で確定できるもの**に限っています。

**Q2. 自分が判定する164件は、どういう基準で選ばれたのか？**

**文献キーのMD5による決定論的な抽出**です。主題や難易度で選んでいません。
1,052件の15%にあたり、3名全員が判定します。κ を算出するために、
著者だけでなく全員が同じ集合を見る必要があるためです。

**Q3. Venueで絞っているなら、残ったものは全部「良い論文」では？**

掲載先の格と、本レビューの主題に合うかは別です。CORE A* の会議にも
本サーベイと無関係の論文は大量にあります。`ランク` 列を判定材料にしないでください
とお願いしているのはこのためです。

**Q4. 引用探索の257件だけフィルタが甘いと聞いたが、判定を緩めるべきか？**

いいえ。**判定基準は完全に同一**です。フィルタ層は「DB間の取得差の吸収」が目的で、
DB検索で取得していない文献には吸収すべき差が存在しないため適用していないだけです。
`取得経路` 列は PRISMA の左右カラム別報告のための記録にすぎません。

**Q5. 要旨が無い文献はどう扱えばよいか？**

タイトルのみでの判定になります（担当164件中35件）。無理なら `Unsure` にしてください。
これは意図的な設計で、**要旨が無いことを理由に機械が落とすと「メタデータ品質による除外」
になってしまう**ため、あえて人手に送っています。

## B. 査読者（ACM CSUR）から出そうなもの — 弱点を突く質問

**Q6. Phase 1.5「フィルタ層」は PRISMA の標準的なフローに無い段だが、正当化できるか？**

**最も突かれやすい箇所です。** 現状の正当化は、標準的な慣行ではなく
**自前の実測**（DB間で検索scopeが異なるという §2 の表）に置いています。

準備すべき回答:
- 目的が**適格性判定ではなく取得バイアスの是正**であること。独立した段として報告し、
  適格性で落とす段と混ぜていないこと
- 適用しなければ「どのDBで拾われたか」で適格性が変わるという、より深刻な問題が残ること
- フェイルセーフにより、メタデータ欠落を理由とした除外を行っていないこと

> **未整備:** この手続きに相当する先行事例（サーベイ論文での類似手続き）を
> **まだ調べていません**。「標準ではないがこういう前例がある」と示せると強い。
> 逆に前例が無ければ「新規の是正手続きとして提案し、影響を数値で開示する」
> 立て付けにする必要があります。

**Q7. Phase 2 の除外の60%が「Venue未照合」だが、これは質の判断ではないのでは？**

**そのとおりで、最大の弱点です。** 3,085件が名寄せの失敗で落ちています。

準備すべき回答:
- Rev.12 で正規化に構造ガードを入れ、`venue_aliases.csv` を最優先に再設計したこと
- 監査列（`Match_Stage` / `Match_Guard_Note`）で誤照合を可視化していること
- 未照合上位50件を監査し、**高ランクの表記ゆれによる脱落は0件**だったこと
- それでも残るリスクをスノーボーリングで補っていること

**Q8. Known-Item recall が 47.1% では低すぎないか？**

低いです。隠さずに報告します。脱落の内訳は分析済みで、
**Venueホワイトリスト（step2で6件）とクエリのG1ギャップ**が主因と特定されています。
「引用探索で29.4%→47.1%に改善したが限界が残る」と書き、
残る脱落の原因を段ごとに帰属させて示すのが誠実な扱いです。

**Q9. SJR Q1のみ・CORE A/A*のみは厳しすぎないか？主題関連誌を落としていないか？**

Q2まで広げると826件/332誌が加わり、Multisensory Research・QJEP・Neuropsychologia など
**主題関連誌が含まれます**。この事実は Threats で具体名を挙げて報告します。

**Q10. Phase 3b の liberal accelerated は二重スクリーニングとして弱いのでは？**

単独スクリーニングは13%見落とす（感度86.6%）のに対し2名は3%（97.5%）という
RCTの実測があります（Gartlehner et al. 2020, `rule.md` §5 [R1]）。

> **注意:** この論文が検証したのは**1名 vs 2名**であって liberal accelerated ではありません。
> また結論は「rapid reviewでは有効な選択肢」という条件付きで、本サーベイは rapid review
> ではありません。**「除外側を二重化することでこの差を埋める」は著者の論証**であり、
> 引用元の結論ではない、という切り分けを本文で明示する必要があります。

**Q11. `liberal accelerated` の一次出典は？**
