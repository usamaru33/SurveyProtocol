## 2. 設計の原則

1. **独立性を保つ。** 評価者ごとに別ファイル。各シートには自分の担当分だけを入れ、他者の判定列は存在させない
   (Phase 3b と同じ。Phase 4 では「通常の二重評価」なので、独立性はより重要)。
2. **「Unsure」を許すが、最終判定には残さない。** Phase 3b は未解決を Include に倒す(再現率優先)が、
   Phase 4 は最終判断なので**倒さない**。Unsure は協議で必ず Include か Exclude に決める。
3. **基準ごとに判定を残す。** 総合判定だけだと、不一致の原因(どの基準で割れたか)が分からない。
   Phase 3b の κ 診断で「I 基準に不一致が集中」(Rev.27)したのと同じ事態を、今回は最初から可視化する。
4. **全文に根拠を残す。** 各 Exclude に、根拠のページ・引用を残す(PRISMA の監査性。協議の時間も減る)。
5. **LLM は使わない**(rule.md Rev.2)。

## 4. 判定シートの列

評価者ごとに 1 ファイル(`phase4_sheet_<id>.xlsx` / `.csv`)。**★ が評価者の記入列**。

| 列 | 内容 | 備考 |
|---|---|---|
| `record_id` | 文献 ID | 固定 |
| `title`・`doi`・`venue`・`year` | 書誌 | 固定 |
| `pdf` | `fulltext/pdf/<ID>.pdf` への相対パス | 固定。未取得は空 |
| `P_check` ★ | P(健常成人): `Y` / `N` / `?` | 下の「基準の運用」参照 |
| `I_hmd` ★・`I_scale` ★ | I を 2 列に分ける(2026-10-19 確定)。`I_hmd`: HMD の VR か / `I_scale`: 自己・環境のスケールに関係する操作・刺激があるか。`Y` / `N` / `?` | 旧: `I_check` 1 列 |
| `C_check` ★ | C(比較対象がある): `Y` / `N` / `?` | |
| `O_check` ★ | O(スケール変容の定量指標): `Y` / `N` / `?` | |
| `S_check` ★ | S(実証的なユーザー実験): `Y` / `N` / `?` | |
| `decision` ★ | `Include` / `Exclude` / `Unsure` | |
| `reason` ★ | Exclude のときの主理由(プルダウン) | 語彙は §5 |
| `evidence` ★ | 判定の根拠(ページ・引用) | Exclude では必須 |
| `memo` ★ | 自由記述 | 境界例は必ず書く |

**基準の運用**(rule.md の PICOS を操作化したもの。**下線の 4 点は著者の判断が要る**):

- **P:** 健常成人のみが対象。小児・高齢者・患者・特定の専門職集団は N。混合サンプル(健常成人が主で一部が他)は、結果を分けて報告していれば健常成人の部分で判断する。<u>(混合サンプルの扱い)</u>
- **I:** HMD を用いた VR(デスクトップ・AR/MR・CAVE は N)で、身体・空間スケールの操作か多感覚刺激の提示がある。<u>(「多感覚刺激のみ」が単独で I を満たすか。Rev.27 の境界例メモ 18 件の扱い)</u>
- **C:** スケール操作の有無、倍率間、視覚単独 vs 多感覚の比較のいずれかがある。単一条件の記述研究は N。
- **O:** 自己または環境のスケール変容を測る**定量**データ(主観的サイズ推定・距離知覚・アフォーダンス判断・身体所有感・客観的運動出力)。<u>(身体所有感だけで O を満たすか)</u>
- **S:** 実証的なユーザー実験。総説・技術提案・シミュレーションのみは N。

`decision` の規則(シート上の検査に使う): 5 基準がすべて `Y` なら Include、1 つでも `N` なら Exclude、`?` があれば Unsure。
**この規則と `decision` が食い違う行は、検査で警告する**(記入ミスの検出)。

## 5. 除外理由の語彙

Phase 3b の語彙(`EXCLUDE_REASONS`)を**そのまま流用**する。Phase 3b と Phase 4 で語彙が違うと、PRISMA 上で理由を統合できない。
Phase 4 で追加するのは次の 2 つだけ:

- `全文を入手できない`(PRISMA 2020 の「reports not retrieved」。判定ではなく状態として記録)
- `主題は適合するが基準の運用が割れた` は**作らない**(それは Unsure で協議に回す)

**主理由の優先順位**(複数の基準に抵触するとき、1 つだけ記録する。評価者間で理由が割れて κ が下がるのを避けるため):
`S` → `P` → `I: HMD-VR でない` → `I: スケール操作/多感覚刺激が無い` → `O` → `C`。
(判定そのものに影響しない。除外理由の**報告**を揃えるためだけの規則。)
ただし、基準別の列(§4)には全抵触を残すので、情報は失われない。

## 6. 全文が入手できない文献の扱い

- 未取得のまま、評価者に配らない。
- **取得の期限を決める**(推奨: 評価の開始から 4 週間)。それでも入手できない場合は、「全文を入手できない」として PRISMA に報告する。
- 入手できない文献を Title/Abstract だけで判定しない(Phase 3b の判定を Phase 4 に持ち込まない)。
- 重複記録 2 組は **2026-10-19 に代表を決めた(Rev.28)**: Rdf3e2d120(R8e3a14279 を統合)、Rb3c541a72(R3d28d9842 を統合)。代表は DB 由来で DOI が正しい側。統合した記録は配らない(`fulltext/duplicates_merged.csv`)。

## 7. 保留中の判断と、この設計との関係

rule.md・PROGRESS_LOG(2026-09-11)の保留 3 件+Rev.26 は、スクリーニング完了後に決める扱いだった。**スクリーニングは完了したので、決定の時期が来た。**
ただし、適格性評価(本設計)と分類(Taxonomy)は別なので、適格性評価の開始は保留に左右されない。

| 保留事項 | 適格性評価への影響 | 分類への影響 |
|---|---|---|
| Rev.26: 軸 1 の下位区分(Visual-Global/Local/Perspective)の定義 | なし | **分類の開始前に決める必要がある** |
| 軸 3 の既定コーディング規則(著者非明示のとき推定するか、第 4 値 "Not stated" を設けるか) | なし | 同上 |
| タキソノミー・コーディングに κ を付けるか | なし | 同上 |
| 軸 1 に非視覚カテゴリを設けるか | なし | 同上 |

**提案:** 適格性評価の判定シートで、分類に依存しない「事実の抽出」を同時に集める(下記の抽出列)。
分類の判断が決まったとき、全文をもう一度読まなくて済む。

**事実の抽出列(自分の判定が Include か Unsure の論文だけ、担当ペアの 1 名が記入)** — 2026-10-19 に確定(Rev.29)。列と形式(17 列、必須 10)は `docs/reference/phase4_reviewer_guide.md` §3.5。

これは分類(軸 1〜3)ではないので、適格性評価の κ に影響しない。分類の κ(保留事項の 3 つめ)は別に決める。
