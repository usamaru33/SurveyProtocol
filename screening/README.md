このフォルダは、システマティック・レビューの **Phase 3b（Title/Abstract スクリーニング）**
の作業ファイルと記録一式です。**監査可能性のため supplementary material として公開します。**

- 手順の詳細: [`../docs/protocol/screening_protocol.md`](../docs/protocol/screening_protocol.md)

- 変更履歴: [`../docs/log/protocol_changelog.md`](../docs/log/protocol_changelog.md) Rev.17 / Rev.18

> 生成スクリプトはシートの作成と集計のみを担当します。

## 1. 何を判定しているか

検索でヒットした 14,682 件を機械的に絞り込んだ **1,052 件** が判定対象です。
評価者はタイトルと要旨だけを読み、「全文を読む価値があるか」を3択で判定します。

| 取得経路 | 件数 | PRISMA |
|---|---|---|
| データベース検索 | 795 | 左カラム |
| 引用探索（スノーボーリング） | 257 | 右カラム |

判定基準は両者で同一です。`取得経路` 列は PRISMA の左右カラム別報告のための記録にすぎません。

## 2. 方式: liberal accelerated

> **1人が Include にすれば通す。Exclude するには2人必要。**

| 段 | 内容 | 担当件数 |
|---|---|---|
| **stage 1** | 全 1,052 件を著者が判定 | 著者 1,052 |
| | うち **校正セット 223 件（20%）は3名全員**が独立に判定 | Kataoka 223 / WATANABE 223 |
| **stage 2** | 著者が Exclude / Unsure にしたものだけ第2評価者が確認 | Kataoka 最大 420 / WATANABE 最大 409 |

**なぜ非対称なのか。** この段階のエラーは非対称です。誤 Exclude は回復不能（全文を読む機会が
永久に失われる）ですが、誤 Include は Phase 4 の手間が増えるだけです。一方、単独
スクリーニングが関連文献を見落とす率には RCT の実測があります。そこで
**除外の方向にだけ2名を要求**し、全件二重化の工数を避けつつ感度を保っています。

> 見落とし率の数値と出典は [`../docs/protocol/rule.md` §5 [R1]](../docs/protocol/rule.md#5-方法論の参考文献)
> に集約してあります。

**κ は校正セット 223 件（20%）でのみ算出します。** 除外プールだけで計算すると著者の判定に
分散が無く κ が構造的に常に 0 になるためです（`protocol_changelog.md` Rev.17）。

**割当は決定論的です**（校正セットの抽出・第2評価者の振り分けとも文献キーの MD5）。
乱数を使っていないので、誰がいつ再実行しても同じ割当になります。

## 3. ファイルの読み方

| ファイル | 内容 | 誰が触るか |
|---|---|---|
| `assignment.csv` | 割当の正（record_id・block・担当2名・校正セット指定） | **編集しない** |
| `sheet_<id>.csv` | 生成時の雛形（機械可読の正） | 触らない |
| `sheet_<id>.xlsx` | **各評価者の作業ファイル** | 本人のみ |
| `EXAMPLE_記入見本.xlsx` | 記入例5件。全員に同じものを配布 | 参照のみ |
| `stage2_sheet_<id>.xlsx` | stage 2 の確認用（著者の stage 1 完了後に生成） | 本人のみ |
| `consensus_worklist.csv` | 不一致と Unsure だけを抜いた協議リスト | 協議で記入 |
| `final_decisions.csv` | 最終判定（Include が Phase 4 へ進む） | 自動生成 |

### ⚠️ 他人のシートは開かないこと

二重スクリーニングの妥当性は **評価者が互いの判定を見ないこと** に依存します。
先に書いた側の判定が見えると独立性が壊れ、κ が意味を失います。
評価者ごとにファイルを分けてあるのはこのためです。判定についての事前の相談も行いません。

`stage2_sheet_*.xlsx` は著者の判定列を空にしてありますが、**そこに含まれること自体が
「著者が Exclude / Unsure にした」という情報**です。そのため stage 2 のシートは
著者の stage 1 完了後にしか生成しません。

## 4. 記入のしかた

`.xlsx` の「判定」シートで、★ が付いた3列だけを埋めます。他の列はロックしてあります。

| 列 | 記入内容 |
|---|---|
| `判定 ★` | `Include` / `Exclude` / `Unsure`（ドロップダウン） |
| `除外理由 ★` | **Exclude のときは必須**。下の統制語彙から1つ（ドロップダウン） |
| `メモ` | 任意。ただし除外理由が `その他` のときは必須 |

### 除外理由の統制語彙（Rev.18）

| 選択肢 | 定義 |
|---|---|
| `P: 対象者が不適合` | 健常成人でない（小児・高齢者・患者・特定の専門職集団など） |
| `I: HMD-VR でない` | デスクトップ画面・AR/MR・CAVE・実環境のみなど |
| `I: スケール操作/多感覚刺激が無い` | 身体・空間スケールの操作も多感覚刺激の提示も行っていない |
| `O: スケール知覚の測定が無い` | 自己・環境のスケール変容を測る定量指標が無い |
| `S: ユーザー実験が無い` | 技術提案・デモ・シミュレーションのみ |
| `S: 原著論文でない` | 総説・サーベイ・抄録のみ・ポスター・基調講演・書籍など |
| `スコープ外(主題が無関係)` | 基準を当てるまでもなく本レビューの主題と無関係 |
| `重複(同一研究の別報告)` | 既に対象に含まれている研究の別報告・拡張版 |
| `その他` | 上のどれにも当てはまらない。**メモへの記述必須** |

> ### 除外理由の優先順位（2026-08-24 追加 / `../docs/log/protocol_changelog.md` Rev.24）
>
> **複数該当するときは、下の順位で最も上位のものを1つ記録する。**
> 「最も明白なもの」は評価者ごとにぶれるため、順位を固定して決定論にした。
>
> | 順位 | 選択肢 |
> |---|---|
> | 1 | `重複(同一研究の別報告)` |
> | 2 | `スコープ外(主題が無関係)` |
> | 3 | `S: 原著論文でない` |
> | 4 | `S: ユーザー実験が無い` |
> | 5 | `P: 対象者が不適合` |
> | 6 | `I: HMD-VR でない` |
> | 7 | `I: スケール操作/多感覚刺激が無い` |
> | 8 | `O: スケール知覚の測定が無い` |
> | 9 | `その他`（他の8つに当てはまらないときのみ） |
>
> **原理: 上位ほど、下位の基準を評価する前提そのものが崩れている。**
> 重複＝独立した研究として数えない → スコープ外＝PICOS を当てる対象でない →
> S 2つ＝研究の実体が無く P/I/O を評価できない → 実体のある研究に PICOS を順に適用。
>
> **併記は求めない。** 選ばなかった理由をメモに書き足す必要はない。
> したがって**理由別の集計は「上位に一本化された件数」であり、内訳は復元できない**
> （→ Threats to Validity）。
>
> **Include/Exclude/Unsure の判定は変わらないため κ に影響しない。**
> 目的は、Rev.21 の κ 低下時診断（除外理由の分布から割れた基準を特定する）を機能させること。
>
> 語彙・シートは**変更していない**（Rev.19 の凍結維持）。

> **`S: 原著論文でない` の解釈（2026-08-20 補足 / `../docs/log/protocol_changelog.md` Rev.20）**
>
> 上表に含まれる「ポスター」は、**実験を伴わない**ポスター発表を指す。
> **実験を報告しているポスター/ショートペーパーは Include**（Rev.14 の S 基準運用。
> gold set の in-scope 17件のうち4件が2ページの会議論文で、うち1件は唯一の聴覚の例）。
> **ページ数は除外理由にならない。判断するのは内容。**
>
> 語彙の文言は配布時のまま**変更していない**（Rev.19 の凍結維持）。
> **stage 2 のシート生成時も語彙は変えず、同じ補足を書面で添えて配布すること。**

- 自由記述をやめたのは、PRISMA が求める除外理由の記録を**そのまま集計できる形**にするため。
  自由記述だと著者が事後にコーディングすることになり、その作業自体が判定への事後介入になる。
- **複数該当するときは、上記の優先順位で最も上位のものを1つ**選ぶ（PRISMA の primary reason 慣行）。
  **併記は求めない**（`メモ` への書き足しは不要。`メモ` が必須なのは `その他` のときだけ）。
- **`C`（比較対象）は選択肢にありません。** 比較条件は要旨に書かれないことが多く、
  この段階で C を根拠に落とすと誤除外（回復不能）になるため、判断は Phase 4 に送ります。
- 「その他」の件数と内訳は Threats to Validity で報告します。一定数を超えたら語彙を見直します。

### 判定の原則

> **除外できると確信できないものは残す（Include に倒す）。**

全文を読めば分かることを、この段階で切らないためです。迷ったら `Unsure`。
Unsure は協議対象になるので、無理に二択にする必要はありません。

### 参考列（判定には使わない）

| 列 | 意味 |
|---|---|
| `概念群` | 検索クエリの3概念群が Title+Abstract にいくつ成立するか（0〜3）。**読む順序のトリアージ専用**。シートはこの降順→新しい年順に並べてある |
| `校正セット` | `Y` は3名全員が判定する分（κ の算出に使う）。**判定基準は `N` と同じ** |
| `要旨有無` | `N` は**要旨が無くタイトルだけで判定する**文献（191件 / 18.2%） |
| `要旨の出所` | `database` = 検索結果に元からあった / `enriched` = DOI から外部補完（134件）/ `none` = 取得できず。**`enriched` も判定材料としては同じように扱う** |
| `ランク` | 掲載先の CORE/SJR ランク。Phase 2 で既に基準を満たしているので判定材料にしない |

## 4.5 判定を速くする閲覧アプリ（任意・著者用）

1,052件を Excel のセルで読むのは遅い（要旨は中央値1,466字あり、既定の行高では冒頭5行しか見えない）。
そこで**読む速度だけを上げる**ローカルアプリを用意した。

```bash
python -X utf8 scripts/make_review_app.py            # → screening/review_author.html
# ブラウザで開き、キーボードで判定 → E キーで decisions_author.csv を書き出す
python -X utf8 scripts/apply_review_decisions.py --id author --input decisions_author.csv
```

- 1件ずつ全画面表示。**`i`=Include / `u`=Unsure / `1`〜`9`=Exclude+除外理由**（1打で判定+理由）。
  `j`/`k` 移動、`m` メモ、`z` 取り消し、`h` ハイライト切替、`?` ヘルプ
- 判定は入力のたびにブラウザに保存される（localStorage）。中断・再開できる
- 校正セット（`calibration=Y`）は **★ バッジと警告帯**を出す。**表示の正は `assignment.csv`**
  （`sheet_*.csv` は生成時点のスナップショットで、Rev.22 の 15%→20% 引き上げに追随していない）
- 反映スクリプトは書き込む前に検証する: 担当外ID・不正な判定値・統制語彙の外の理由・
  Exclude なのに理由が空・「その他」なのにメモが空・**既存の判定の上書き**（`--force` が要る）。
  書き込み前に xlsx のバックアップを取る

> ### ⚠️ このアプリは判定を自動化しない
>
> **キーワードで Include / Exclude を自動で書き込む機能は、意図的に持たせていない。**
> κ は校正セットで **著者 × 各評価者** のペアについて算出する（`score_screening.py`）。
> 著者の判定が正規表現の出力だと、κ は「評価者間の一致」ではなく
> **「人 vs 正規表現の一致」**を測ることになり、報告値が無意味になる。
> `rule.md` が「意味的判断は人手ダブルスクリーニング」と定めているのもこのため。
>
> `--rules` で渡すキーワードは**ハイライトと並べ替えにのみ**使われる。判定は書き込まない。

### 要旨の日本語訳（任意）

```bash
python -X utf8 scripts/translate_abstracts.py --estimate                    # 見積もり(通信なし)
python -X utf8 scripts/translate_abstracts.py --engine deepl --only-calibration
python -X utf8 scripts/make_review_app.py --translations screening/abstract_ja.json
```

閲覧アプリで **`t`** を押すと 原文のみ → **対訳** → 訳のみ を切り替える。**既定は対訳**で、
訳文には常に「機械翻訳（参考）」の見出しが付く。

- 訳文は `screening/abstract_ja.json` に固定する。各エントリに **原文の SHA-1・エンジン名・
  実行日**を記録するので、**著者が実際に読んだ訳文を第三者が再現できる**
- 原文が差し替わったのに古い訳が残っている場合、アプリは**その訳を採用しない**
  （SHA-1 が一致しないため。読んでいる訳と判定対象がズレるのを防ぐ）
- 再実行しても既訳は翻訳し直さない。中断してもそこまでは保存される
- 分量: 要旨のある861件で **約128万字**（DeepL 無料枠 50万字/月の 2.6 倍）。
  校正セットだけなら 179件・約27万字で無料枠に収まる

> ### ⚠️ 判定は原文に対して下す
>
> 機械翻訳は `head-mounted display` と `desktop display`、`patients` と `participants` のような
> **適格性を反転させる語**を取り違えうる。訳文だけで判定すると、その誤りが判定の誤りに
> そのまま化ける。だから「訳のみ」を既定にしていない。
>
> **さらに κ への影響がある。** κ は校正セット223件で **著者 × 各評価者** について算出する。
> 著者だけが訳文を読み、評価者2名が原文を読むと、**3名が別の刺激を判定している**ことになり、
> κ に翻訳のブレが混入する。訳を使うなら、
> **(a) 3名に同じ訳を配る か (b) 使用を Threats に開示する** のどちらかが要る。

**要旨中のハイライトについて（開示事項）。** 検索クエリの3概念群（`search_strings.md` Rev.6）と、
PICOS の判断材料になりやすい語を色分けする。**残す手がかりと落とす手がかりを対称に**入れてある
（`participants`/`we conducted` と `desktop`/`patients`/`we propose` の両方）。片側だけを
強調すると誘導になるため。`h` で無効化できる。表示補助であって判定基準ではない。

## 5. 再現手順

```bash
cd SurveyProtocol

# 1. 割当と雛形 CSV を生成（決定論的。何度実行しても同じ割当になる）
python -X utf8 scripts/make_screening_sheets.py

# 2. 評価者が記入する Excel 版を生成
python -X utf8 scripts/make_screening_xlsx.py

# 3. 記入見本を生成（全員に配る）
python -X utf8 scripts/make_screening_example.py

# --- 著者が stage 1 を終えたら ---
python -X utf8 scripts/make_screening_stage2.py
python -X utf8 scripts/make_screening_xlsx.py --prefix stage2_

# --- 全員の記入が終わったら ---
python -X utf8 scripts/score_screening.py
```

> **既存の .xlsx は上書きされません。** 記入途中で再生成しても作業は消えません
> （存在するファイルはスキップされます）。作り直すには `--force` が必要です。

`score_screening.py` の出力:

1. **記入状況の検査** — 未記入・不正値・担当外レコード・Exclude なのに理由が空・
   統制語彙の外の値・「その他」なのにメモが空
2. **理由別の除外件数**（PRISMA の報告にそのまま転記できる形）
3. **ペアごとの Cohen's κ とその平均** — 3カテゴリ版が主報告。Unsure→Include に寄せた
   2カテゴリ版も参考として併記（**両方を出したうえで選ぶ**ことで恣意的に見えないようにしている）
4. `consensus_worklist.csv` — 協議リスト

協議で解決しない場合は **`Include` に倒して Phase 4 へ送ります**（再現率優先）。
その場合は `consensus_note` に「協議で解決せず → Include」と明記し、後から件数を数えられる
状態にします。

## 6. 既知の制約

- **要旨欠落 191件（18.2%）** — DB検索側 63件 / 引用探索側 128件。Rev.16 で DOI から
  134件を外部補完した後の残余。これらは**タイトルのみでの判定**になる。件数は
  Threats to Validity に明記する
- 判定は人間の主観に依存する。緩和策は二重評価・κ の報告・協議記録の公開だが、
  主観であること自体は消えない（Threats に明記済み）
- `概念群` によるトリアージは読む順序を変えるだけで、判定対象は全件のまま。
  **順序が判定に与える影響（先に読んだものほど厳しく／甘くなる等）は統制していない**

## 7. バージョン管理での扱い

各評価者のシート `sheet_*.csv` / `sheet_*.xlsx` は **記入中は `.gitignore` で追跡しません**。
3人分がリポジトリに入ると互いの判定が見えてしまい、独立性が壊れるためです。

ただしこれらは `rule.md` が要求する監査証跡でもあるので、
**スクリーニング完了後に `git add -f screening/sheet_*.csv` で必ず追跡に加えてください。**
割当表・協議リスト・最終判定・この README は最初から追跡しています。
